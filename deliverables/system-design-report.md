# 招采数据智能分析引擎系统设计报告

初赛作品说明 · 2026-10-11 · 版本 1.0

## 核心成果预览

本作品面向采购业务人员和数据核查人员，将分散在公告与复杂附件中的信息转成可检索的实体、可解释的关系和可追溯的复核记录。系统已形成材料导入、七字段抽取、五类关系查询、来源证据查看、人工复核和公告版本比较的完整操作链路。

| 业务需求 | 已实现能力 | 可演示结果 |
|---|---|---|
| 从复杂材料取数 | HTML、Office、PDF、图片 OCR、ZIP/RAR/7z；三条抽取路线 | 七字段、采购单位、参与主体、中标记录与解析告警 |
| 从结果回到原文 | 新导入保存文件哈希、来源定位、字段证据与空值状态 | 在公告详情中查看证据片段和来源 |
| 从实体发现关系 | 五类查询、关系线索卡、图搜索、有界 1-hop 子图 | 查看项目数、包数、金额和关联公告 |
| 从候选形成复核记录 | 接受、修正、驳回；保存理由、前后值和候选代次 | 复核事件与机器候选分离保存 |
| 从单次导入扩展到批处理 | 目录浏览预检、有界并发、检查点、暂停续跑 | 可恢复任务和逐公告结果 |

截至代码基线 c1fc4c4 的验收记录，后端 662 项测试通过，前端 80 项通过，Ruff 和生产构建通过。2026-09-30 全量材料快照覆盖 1,038 条公告和 13,136 个附件叶文件。测试与材料处理数量属于团队工程验证，不能替代字段质量指标。

## 1 业务需求与技术选型

任务一提取产品或服务名称、品目、品牌、规格型号、单价、数量、总价，并保存采购单位、投标主体和中标记录。任务二围绕采购单位、供应商、项目和采购包建立关系，支持五类指定查询。任务三通过 Vue 分析台提供导入、检索、统计、图展示和复核入口。

系统优先保存事实和来源。原文未披露的信息保留空值；名称型包号只有在明确标签和值的连续证据通过校验时接受。自动抽取结果作为候选进入系统，人工修正以独立覆盖记录保存，不回写原始机器候选或自动改变统计结果。

| 技术选择 | 采用理由与职责 |
|---|---|
| Vue 3 与 Vite | 将分析、图搜索、证据弹层、复核和版本历史组织为可交互工作台 |
| Python 与 FastAPI | 统一多格式解析、模型调用、严格结构校验和业务 API |
| SQLite | 每数据集独立文件，部署轻量；承担写入、默认查询和图投影 |
| Neo4j | 可选五类分析后端；连接、同步或查询失败时按请求回退 SQLite |
| Qwen 或 DeepSeek 兼容 API | 配置化使用模型语义能力；规则路线保留离线处理能力 |
| 本地 OCR 与 Office 转换 | 为扫描件和旧式文档建立统一文本入口，记录处理来源与告警 |

## 2 总体架构

数据依次经过内容识别与归档展开、文本与表格解析、三路线抽取、用途与证据校验、候选持久化，再由查询和复核模块消费。解析、模型请求与任务队列分别设置并发边界，避免批处理无限累积请求和文档对象。

浏览器通过 FastAPI 访问当前数据集；X-Dataset-ID 控制数据集选择。五类分析 API 可读取 Neo4j 数据集镜像，响应报告实际后端；图搜索和关系线索读取 SQLite。公告版本保存不可变快照，版本比较读取冻结证据，不覆盖原版本。

## 3 数据模型与统计口径

| 数据对象 | 核心职责与关系 |
|---|---|
| organizations | 采购单位、供应商和投标主体；保留原名与别名，保守归一 |
| projects 与 packages | 公告项目和采购包；项目频次与包数分别统计 |
| bid_participations | 主体参与采购包的关系；区分 winner、nonwinner、unknown |
| awards | 明确中标关系及其金额；不以项目总额替代主体中标金额 |
| procurement_items | 标的七字段、来源定位、字段证据及抽取方法 |
| 复核事件 | 决定、操作者、时间、理由、前后值、候选代次 |
| 公告版本 | 身份、不可变快照、文件哈希、结构化差异及冻结证据 |

五类查询包括：采购单位的合作供应商与产品供应商；采购单位的高频参与主体和共同参与组合；指定中标供应商的共同竞标者；多供应商的共同采购单位；多供应商共同参与的项目。参与关系默认纳入已记录的 winner、nonwinner 和 unknown，结果未知不推断为未中标。

合作频次按项目去重，并保留包数和包明细。中标金额按唯一 award 记录累加，不按金额相同去重。产品供应商按赛题品牌口径单独展示，其金额只汇总已披露的标的总价，不分摊项目总额或中标交易额。详细定义见 docs/QUERY_SEMANTICS.md。

## 4 功能设计与使用路径

导入者可上传单条公告材料，或在服务器授权根目录内浏览批量材料、预检并创建任务。任务支持模式和 OCR 配置冻结、暂停、续跑、失败重试与幂等入库。

分析者可搜索主体或项目，在受控子图中查看关系，再由线索卡跳转公告证据。卡片可收起长明细，公告详情在视口居中显示并独立滚动。受控自然语言查询先展示解析场景和过滤条件，只执行五类白名单查询，拒绝任意 SQL、Cypher 和写操作。

复核者可按缺字段、证据缺失、OCR 告警、default 包号和金额冲突排序查看候选。版本历史可比较前后公告和附件变化；身份不明确的材料独立保存并提示确认。版本功能不自动把分析切换为“只统计最新版本”。

## 6 部署与运行保障

仓库提供依赖清单、环境示例、启动与停止脚本、离线样例、账号配置和局域网诊断。运行入口见 README.md，技术环境与命令见 docs/DEVELOPMENT.md。模型端点通过配置接入，无模型时可用 rules 路线完成离线导入和查询。

评审会话使用 HttpOnly、SameSite=Strict Cookie；HTTPS 部署启用 Secure 属性。批量目录访问限定在 INTAKE_ROOT，部署者负责该目录的文件写权限。API Key、密码和本地数据库不进入公开源码包。

源文件不可用、专有格式不支持和证据缺失均以明确状态呈现。应用不长期保存原始文件字节，历史缺失证据不补造。图投影使用 SQLite，Neo4j 控制五类分析 API；并发机制面向单机服务，不提供跨主机分布式锁。
