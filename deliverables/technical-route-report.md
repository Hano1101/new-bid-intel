# 招采数据实体抽取技术路线对比报告

初赛过程性文档 · 2026-10-11 · 版本 1.0

## 1 方案选择与适用范围

系统实现 rules、model、hybrid 三条路线，共用材料解析、结构化 schema、用途过滤和来源证据保护。业务导入选择 hybrid 以结合结构规则与模型语义能力，规则路线用于离线和低成本场景，模型路线作为语义覆盖的可选方案。该工程选择兼顾可核查性与运行条件，并不宣称 hybrid 在所有质量指标上领先。

| 路线 | 主要工作 | 优势 | 主要控制措施 |
|---|---|---|---|
| rules | 显式标签、表格、包号及金额解析 | 低成本、可重复、离线可运行 | 排除章节标题、联系块和附件占位；保留来源 |
| model | 自由文本与复杂上下文抽取 | 补充规则难覆盖的语义 | 严格 JSON/schema、来源与包号证据校验；失败隔离 |
| hybrid | 规则与模型候选对齐和融合 | 结合结构定位与语义候选 | 一对一匹配、数值冲突保护、合法重复记录保护 |

OCR 是三条路线共同的文本入口，不是单独的最终抽取方案。扫描件识别后仍保存 OCR 状态和告警，以便人工复核。系统没有模型训练或 LoRA/QLoRA 微调过程，创新集中在材料治理、证据约束、候选融合和可恢复任务编排。

## 2 抽取流程

系统先识别真实文件内容并展开归档，限制成员数、深度和展开大小；随后解析正文、表格、Office、PDF 和图片。规则与模型输出统一七字段及主体结构。模型输出进入数据库前还需通过 schema、当前采购用途、包号证据和融合校验。

名称型包号必须同时具备明确标签和值的连续证据；无法建立可靠映射时保留 default。参考资料或历史合同中出现过的标的，不因文本匹配就被认定为本次采购。来源不充分的候选保留可解释警告，供人工判断。

## 3 本地路线比较

以下是 2026-10-09 的历史开发回归记录：24 条 reviewed 公告，attachments 范围，模型配置名 qwen3.8-max，三条路线均完成 24/24。样本已参与开发调试，使用当时的 Gold v1 和预测；本表不是当前代码重跑结果，也不是独立泛化成绩。

| 路线 | 字段加权分 | 完整记录加权分 | 公告级包号集合精确对齐 |
|---|---:|---:|---:|
| rules | 63.28% | 21.93% | 14/24（58.33%） |
| hybrid | 64.67% | 27.03% | 9/24（37.50%） |
| model | 68.42% | 32.69% | 10/24（41.67%） |

本表采用团队本地 official_qa profile，按赛题答疑的 P/N 四格解释计算：Accuracy = (TP + TN) / (TP + FP + TN + FN)，Precision = TP / (TP + FP)，Recall = TP / (TP + FN)。赛题加权公式为 0.4 × Accuracy + 0.3 × Precision + 0.3 × Recall。

official_qa 是对答疑文字的可复现本地实现，不是主办方评分器。错值、空槽、完整记录与实体匹配的边界见 docs/EVALUATION.md。特别是完整记录加权分不能解释成全部七字段完全正确的占比；包号指标则要求整条公告的包号集合完全一致。

同一批预测在模型路线的本地字段和记录指标上较高，规则路线在包号集合对齐上较高。模型带来的字段覆盖并未自动解决包号映射。因此系统保留三条路线配置和证据保护，不用单一分数代替业务选择。

Gold v2 已于 2026-10-10 对旧预测做 local_proxy 离线重评分：rules 字段/记录加权分 55.13%/12.30%，hybrid 51.71%/9.32%，model 55.89%/7.92%。这是一组不同 Gold 版本、不同指标 profile 的结果，不能与上表作直接升降比较，也不代表修复后重新抽取的分数。

## 4 关键工程改进与证据

| 改进 | 已观察证据 | 适用范围 |
|---|---|---|
| 历史附件用途过滤 | 两份历史附件缓存候选由 5、9 条降为 0 | 定向样例；不是全量收益 |
| PDF 页标记处理 | 完整 PDF 的 9 条历史候选证据可定位，过滤后为 0 | 仅该 PDF 的本地回归 |
| 跨文件候选融合 | 原始模型缓存候选 332→309，包数 59→59 | 缓存候选离线诊断，不是生产预测成绩 |
| cache-only 回放 | 14/24 可回放；hybrid 153→146、model 149→139 | 10 条缺 parse cache 隔离；新模型请求为 0 |
| 有界并发与恢复 | 文档、请求、队列分别设限；暂停续跑、幂等入库 | 单机服务；实际吞吐受材料和服务商配额影响 |

上述诊断针对不同输入和阶段，不能叠加成一个收益数字。旧预测、Gold、缓存和报告保留；修复效果由专项回归证明，不回写历史成绩。

## 5 复现与效率口径

运行比较时固定输入清单、Gold 版本、代码与提示词哈希、模型配置、OCR 配置、并发度、缓存状态和 metric profile。评测器保留逐公告进度、请求数、耗时、token、失败与尝试历史，提供有界并发和显式续跑。运行步骤见 docs/benchmarks/route-evaluation-runbook.md。

赛题处理速率定义为全部公告解析与实体抽取总耗时（含附件）除以公告总篇数，计时从数据集导入完成至结果全部写入数据库。查询效率定义为五个场景各执行一次，从前端发起操作到结果完全渲染的平均时长。局部解析耗时、服务端 API 耗时和含缓存回放应分别报告，不能代替该端到端定义。
