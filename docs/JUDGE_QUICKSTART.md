# 评委快速了解与启动

## 作品简介

本作品把采购公告及其附件转成可筛选、可追溯的标的和主体信息，再用关系分析、证据详情和人工复核支持采购信息审查。系统提供完整的本地运行路径，演示可在不依赖在线模型服务的情况下启动。

## 作品亮点

1. **抽取结果带来源**：公告详情展示候选记录、包号、主体关系、来源文件、文本定位、证据片段、解析警告和可用的文件哈希；无法确认的历史信息会明确提示核验状态。
2. **复杂附件按文件隔离**：系统识别 HTML、Office、PDF、图片和常见归档格式；受损附件、无效下载和不支持的专有格式会保留来源并分类告警，不会因此丢失整批公告。
3. **分析结果可回到公告**：五类采购分析、图关系搜索、有限深度关系网络和关系线索卡使用既定查询口径，提供来源公告和证据入口。
4. **人工复核留有记录**：复核队列支持接受、修正和驳回，并保留操作人、时间、理由及变更前后值。
5. **公告版本可比较**：版本历史记录公告与附件变化，支持查看版本证据和比较语义变化；身份需要确认时会保留待确认状态。

## 启动离线演示

需要 Windows、Python 3.11–3.13、Node.js/npm。依赖首次安装需要网络；安装完成后，离线演示本身不调用模型服务。

在仓库根目录用 PowerShell 运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Configure-ReviewerAccount.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\Start-Demo.ps1 -Offline
```

首次安装依赖请先完成 [`DEVELOPMENT.md`](DEVELOPMENT.md) 的初始化步骤。启动后，脚本会显示分析台地址和标注页地址。打开分析台地址，用评审账号登录；离线模式会创建“离线演示样例（纯虚构）”数据集，并使用规则抽取，不需要 API Key。账号只保存在本机忽略目录中，应通过受控方式提供给评委。

完整安装、模型配置和 Neo4j 可选路径见 [`DEVELOPMENT.md`](DEVELOPMENT.md)；停止脚本和常见问题见 [`REVIEWER_GUIDE.md`](REVIEWER_GUIDE.md)。

## 推荐演示顺序

1. **公告详情**：打开一条公告，查看标的字段、采购单位与投标主体、来源片段及附件告警。
2. **五类分析**：选择查询场景并观察数据范围、金额口径、筛选结果和实际分析后端。
3. **关系搜索与线索**：按单位、供应商或项目搜索，查看受控范围内的关系网络；从线索卡进入来源公告和证据。
4. **人工复核**：查看按数据质量信号排序的队列，对一项候选执行接受、修正或驳回，再查看复核历史。
5. **版本比较**：在准备了同公告多版本材料的数据集中，打开不同版本，比较公告内容、附件变化及各版本的证据。

离线样例用于演示交互流程，数据为虚构内容。版本对比需要先导入具有可靠同一公告身份的不同版本；离线启动不会自动生成历史变更。要展示真实业务材料，可在导入流程选择准备好的公告文件和对应附件；导入回执会显示解析结果与告警。
