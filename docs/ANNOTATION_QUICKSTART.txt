人工标注任务 · 标注员操作卡
===========================

只做人工核对。页面离线工作，不联网、不调模型、不需要 API Key。
详细操作见 docs/ANNOTATION_ANNOTATOR.md。


你要拿到两样东西
----------------
  ① 协调员发给你的专属任务 ZIP
  ② 协调员发给你的标注页面链接（通常以 /annotation.html 结尾）

  缺一样就联系协调员。A、B 只使用各自的 ZIP，不互看答案。
  试标阶段两人会拿到同一组公告；正式任务按各自分配的公告操作。


五步完成任务
------------
  1. 解压 ZIP 到固定文件夹，保留 *.bundle.json 和 sources\ 原件。

  2. 用浏览器打开协调员给的页面链接。

  3. 点“载入我的标注任务”，选中 ZIP 中的 *.bundle.json。
     确认页面显示的任务名和公告数与协调员通知一致。

  4. 逐条对照原文和附件，填写七字段、采购单位、中标方和投标主体。
     解析/OCR 文本只是线索；扫描件要打开原附件。
     对照完成后勾“本公告已对照原文”。

  5. 全部任务核验后点“导出已核验 Gold”，将自动下载的 reviewed JSON
     原样交给协调员，不要重命名。带 .partial 的文件只是未完成进度。


三条原则
--------
  · 原文未披露才留空，不猜、不推理。
  · 页面中的机器预测不是答案，每项都要对照原文。
  · 公司名和品牌名照抄原文，不自行统一简称。


常见情况
--------
  原文“见附件”但附件也没写       → 留空；附件缺失或不可读则联系协调员
  原文“￥1472.6085 万元”        → 填 14726085（换算成人民币元）
  原文数量“2台”                  → 数量填 2（不带单位）
  甲公司中标                     → 中标方和投标主体两处都填它
  未写其他投标方是否中标         → 选“结果未披露”，不要猜
  “甲乙联合体”中标               → 作为一个主体填写，不拆分成员
  原文没有分包                   → 包号填 default


不能勾核验
----------
  标的七字段全空 / 包号为空或重复 / 主体名为空 / 数字格式非法。
  页面会提示问题。修改已核验字段后，页面会撤销核验；需重新对照。

  附件打不开、损坏或像验证码/错误页面时，不要猜，也不要勾核验。
  记下公告 ID 和包号，联系协调员。


中途离开
--------
  自动保存仅在当前浏览器配置里。离开前点“下载进度备份”；
  恢复时用“载入我的标注任务”载入该备份。


注意
----
  Gold 和本地评测结果不是官方成绩，不要对外当作准确率宣称。
  不要外传其他人的任务 ZIP 或整份官方语料。
