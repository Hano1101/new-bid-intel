# 大批量后台处理：服务器材料目录选择器

> 历史报告，已于 2026-10-11 归档。正文保留当时的结论和验证范围；当前实现请查阅[项目文档索引](../../DOCUMENTATION_INDEX.md)。

## 部署配置

在后端部署环境的 `backend/.env` 或进程环境中设置 `INTAKE_ROOT`，指向后端服务账户可访问的服务器材料根目录，例如：

```dotenv
INTAKE_ROOT=/srv/bid-intel/intake
```

Windows 部署可使用实际服务器目录，例如 `INTAKE_ROOT=D:/bid-intel/intake`。配置变化后重启后端。目录浏览、预检和任务创建都会在服务端重新解析所选路径；未配置或根目录不可用返回清晰的 503，越界标识、非目录和逃逸符号链接返回 400。目录浏览器隐藏符号链接和 Windows junction/reparse point；递归字节统计也跳过这些链接，避免越界或循环。浏览器只接收根目录内的相对目录标识，不会收到任意文件读取接口。

扩展现有 jobs router，无需修改 `main.py` 接线：`GET /api/v1/jobs/directories?directory_id=...` 返回子目录及上级标识，`GET /api/v1/jobs/preflight?directory_id=...` 返回预检摘要。根目录标识为空字符串，子目录使用 `/` 分隔的相对标识。`POST /api/v1/jobs` 传入 `directory_id`、`mode` 和 `ocr`；旧的 `source_directory` 入参仍兼容，但也必须位于明确配置的 `INTAKE_ROOT` 内，未配置时不再回退到项目目录。接口保留 `X-Dataset-ID` 数据集上下文。

选择目录后，预检按照现有任务清单规则统计所选目录顶层的 `.html` / `.htm`，并把同名 `.zip`、`.rar`、`.7z` 作为附件；孤立压缩材料会单独列出，没有同名附件的公告显示“无同名附件”。扩展名大小写行为沿用服务器平台与现有任务扫描口径。目录总字节数递归统计常规文件元数据，跳过链接，不读取文件内容，也不解压。任务仍只扫描顶层公告，不递归处理子目录；任务创建后继续使用原有 manifest、checkpoint、暂停、续跑和失败重试流程。创建前拒绝符号链接公告及配对附件。预检返回目录元数据指纹，创建时重新计算；若用户确认前材料有变化，服务端以 HTTP 409 拒绝创建并要求重新预检。

## 手工验收步骤

1. 在 `INTAKE_ROOT` 下准备一个仅用于验收的小目录，放入 `notice.html`、同名 `notice.zip`、`orphan.zip`，再在子目录放一个小文件。不要使用官方全量材料。
2. 重启后端并打开“大批量后台处理”。点击“浏览服务器材料目录”，进入该目录，再点“返回上级”确认导航；页面不应要求输入绝对路径。
3. 点击“预检当前目录”，确认公告数为 1、同名附件数为 1、未配对材料列出 `orphan.zip`，总字节数包含子目录文件，扫描说明明确任务只处理顶层公告。
4. 选择该目录，使用“规则基线”并关闭 OCR，确认所选目录和预检摘要后开始小任务。检查任务显示在当前数据集；切换到其他数据集后不应看到该任务。
5. 对可暂停的小测试任务调用页面暂停和继续入口，确认已完成公告不重复入库；若需要验证失败重试，使用一次性测试材料制造可恢复的文件错误，在修复后显式重试失败公告。现有自动化测试也覆盖检查点续跑、暂停和失败重试。
6. 临时清空 `INTAKE_ROOT` 并重启后端，确认目录浏览显示清晰的配置错误，任务创建接口也拒绝请求。完成后恢复正式配置。
7. 使用一次性测试目录验证空目录和不存在的目录；通过接口尝试 `directory_id=..`、绝对路径、普通文件及指向根目录外的链接，确认被拒绝。Windows 下也检查指向外部目录和指回自身的 junction 不会出现在子目录列表或递归统计中。
8. 在浏览器开发工具中降低网络速度，先预检目录 A，再进入目录 B，确认迟到的 A 预检不会显示成 B 的结果；切换数据集时，旧目录请求不得填入新数据集，必须重新选择并预检。

## 限制

这个选择器只浏览后端已经存在的材料，不能从用户电脑传输文件。普通浏览器的文件选择器通常不会把客户端绝对路径交给服务器；若以后支持从用户电脑上传，必须另做服务器磁盘暂存、断点续传、配额、哈希校验和过期清理。它需要真实传输并暂存数据，不能作为零字节“路径选择”，也不应以一次性巨型 ZIP 上传替代后台任务。

预检会遍历目录元数据来计算总字节数、指纹与清单摘要；超大目录可能需要等待。清单预览最多显示前 200 条公告和前 200 个未配对压缩文件名，统计仍覆盖完整扫描结果。指纹用于发现预检后常见的目录变化；它不构成对恶意并发替换的原子保护。部署时必须把 `INTAKE_ROOT` 设为仅可信操作员/服务账户可写，避免其他用户在任务创建或读取期间替换目录项。处理时现有源文件哈希校验继续生效。
